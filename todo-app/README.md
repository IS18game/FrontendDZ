# Практика 11

## Требования

- Node.js версии 22.12 или новее
- npm

## Установка

Установите зависимости приложения:

```bash
npm install
```

Установите зависимости mock-сервера:

```bash
cd mock
npm install
```

## Разработка

Запустите mock-сервер в одном терминале:

```bash
npm run mock
```

Запустите приложение во втором терминале:

```bash
npm run dev
```

## Окружение

Настройки окружения находятся в `.env.development` и `.env.production`. Скопируйте `.env.example`, чтобы создать локальную конфигурацию. Не добавляйте реальные данные Sentry в файлы, которые отслеживаются системой контроля версий.

- `VITE_API_URL` задаёт базовый URL API.
- `VITE_SENTRY_DSN` задаёт DSN Sentry, если мониторинг включён.
- `VITE_SENTRY_MOCK=true` включает mock-мониторинг без отправки данных.

## Тестирование и проверка

Запустите тесты:

```bash
npm run test
```

Создайте отчёт о покрытии:

```bash
npm run test:coverage
```

Запустите проверку типов и ESLint:

```bash
npm run typecheck
npm run lint:check
```

## Production-сборка

Создайте оптимизированную production-сборку без source maps:

```bash
npm run build
```

Создайте сборку с подробной диагностикой размера бандла:

```bash
npm run build:analyze
```

Приложение использует ленивую загрузку маршрутов, минификацию, tree-shaking, отдельные vendor-бандлы, отчёт о сжатом размере, hash-маршрутизацию, метаданные для отдельных страниц, mock-мониторинг Sentry и метрики производительности браузера.

## Развёртывание на GitHub Pages

Workflow в `.github/workflows/deploy.yml` разворачивает содержимое `dist/spa` после отправки изменений в ветку `main`. В настройках репозитория включите GitHub Pages и выберите **GitHub Actions** в качестве источника. При запуске в GitHub Actions сборка использует базовый URL `/todo-app/`.
